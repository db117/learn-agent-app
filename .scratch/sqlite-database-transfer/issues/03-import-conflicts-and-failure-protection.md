# 03: 旧快照、忙碌与失败保护

**What to build:** 学习者在导入旧快照、应用忙碌、并发传输或数据库替换失败时得到明确且可操作的结果，不会静默覆盖较新进度、截断
TutorAgent 调用或损坏当前数据库。

**Blocked by:** 02: 经校验的 SQLite 整库导入

**Status:** resolved

- [x] 导入快照明显旧于当前数据库时，首次请求只返回快照和当前数据时间比较信息，不修改数据库。
- [x] React 显示旧快照覆盖警告；学习者明确确认后可以再次提交并完成整库覆盖。
- [x] 存在运行中的 TutorAgent 调用时导入返回忙碌冲突，不自动取消或截断 Agent 调用；调用结束后可以重试。
- [x] 同一时间只允许一个数据库导入或导出；并发请求被拒绝或安全串行化，不产生互相覆盖。
- [x] 损坏文件、未知 schema、错误版本、备份失败和替换失败使用稳定、项目自有的错误响应，React 展示对应状态。
- [x] 任何失败路径都保留当前数据库，并清理上传或导出产生的临时文件。
- [x] 替换开始后发生失败时，预导入备份可以恢复当前数据库，不留下部分导入状态。
- [x] 导入成功后旧 TutorEvent 订阅和页面内存状态不再继续向新数据库写入或展示旧数据。
- [x] 自动化测试覆盖旧快照提示与确认、活动 Agent、并发传输、验证失败、备份失败、替换失败和临时文件清理。
- [x] 不增加 Journey 合并、操作日志合并、自动冲突解决或后台同步。
